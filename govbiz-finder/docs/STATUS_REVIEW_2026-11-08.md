## 4. 기업정보·추천 로직과 미입력 처리
- 조건별 결과: MET / NOT_MET / UNKNOWN. 종합: 충족 가능성 높음 / 확인 필요 / 미충족 가능성 높음.
- **미입력 → UNKNOWN(확인 필요)** 이며 부적격 처리하지 않음(테스트로 확인). 미입력 항목은 카드에 입력란으로 표시.
- 규칙 출처: ① DB 규칙 ② 공고 지역 ③ 공고 문구 추정(공고명 시/군 0.7, 업종 0.7, 기술 분야 0.6, 지원대상 규모·업력·인증 0.5, K-Startup 업력 0.6).
- 신뢰도 0.6 미만 규칙은 불일치여도 UNKNOWN으로만 처리. 0.6 이상은 NOT_MET → '맞춤 공고'에서 제외(검색에서는 사유와 함께 표시).

## 5. 데이터 출처·갱신·오류 가능성
- 기업마당: 하루 3회 수집(PC), 1,300여 건. 해외 IP 차단 → 국내 IP에서만 수집 가능.
- 오류 가능성: 지역 태그가 시·도 단위(시·군 공고 → 공고명으로 보정), 자격요건 비구조화(문구 추정), 첨부 URL 토큰 만료(파일명만 보존), PC가 꺼지면 수집 중단.
- K-Startup: 어댑터·테스트 완료, 실호출 **미검증**(키 필요).

## 6. UX·성능·SEO·보안 이슈
- UX: 모바일 상단 메뉴 2줄 줄바꿈, 기업정보 입력 항목 많음(모두 선택이지만 첫 화면 부담).
- 성능: 맞춤 추천이 요청마다 전체 후보(최대 2만 건)를 판정 — 현재 1,300건 수준은 문제없으나 원천 확대 시 캐시 필요.
- SEO: 메타데이터·공고 상세 메타·sitemap·robots 구현. 해설 콘텐츠 페이지 없음.
- 보안: 사업자번호 암호화·마스킹, 기업 관계 관리자 승인, IDOR 방지 테스트. 운영 서버 HTTPS·백업은 배포 후 검증 필요.

## 7. 인계 원칙과 현재 구현의 차이
| # | 인계 원칙 | 현재 | 차이 |
|---|---|---|---|
| G1 | 명시적 충돌일 때만 '조건 불일치' | 공고 문구에서 **추정한** 조건(공고명 시/군·업종·기술 분야)도 불일치 시 제외 | 사용자 요청(안성시·6G·농산물 제외)으로 도입. 원칙과 충돌 → **결정 필요** |
| G2 | 미입력은 판단 보류 | 기업이 '업종 분야/기술 분야'를 비우면 **업종명·보유기술 문구에서 추정**해 불일치 판정 가능 | 기업 측 추정은 '확인 필요'로 낮추는 것이 원칙에 부합 |
| G3 | 4개 상태(적합/추가 확인/불일치/정보 부족) | 3개 상태. 판정 근거가 없는 공고도 '확인 필요' | '정보 부족' 구분 표시 필요(화면만 변경 가능) |
| G4 | DB·스키마 변경은 사전 승인 | 이번 세션에서 마이그레이션 0005~0009를 '직접 진행' 지시에 따라 적용 | 이후 DB·API·인증·배포 변경은 사전 승인 후 진행 |
| G5 | 제휴·상담은 동의 기반 | 미구현 | 설계안 먼저 |
| G6 | 성과지표 관찰 | 분석 도구 없음 | 개인정보 영향 검토 후 도입 |
