# 기업정보 및 맞춤 추천 명세

## 1. 기본 원칙
- 기업정보 입력은 선택사항이다.
- 입력된 정보만으로 추천을 수행한다.
- 미입력은 미충족이 아니라 `확인 필요`다.
- 입력된 사실로 자격 불가가 명확할 때만 `미충족`으로 판정한다.
- 추천은 참고정보이며 최종 신청 자격은 원문 공고와 담당기관 확인이 기준이다.

## 2. 사업자번호 조회
국세청 사업자등록정보 진위확인 및 상태조회 API 연계를 검토·구현한다.
- 사업자 상태조회 API와 진위확인 API의 입력·응답 필드를 공식 문서 기준으로 구분한다.
- 사업자번호만으로 조회 가능한 값(예: 사업자 상태, 과세 유형 등)만 자동 표시한다.
- 대표자명, 상호, 주소, 매출, 종업원 수, 연구소 여부 등은 해당 API가 제공한다고 가정하지 않는다.
- 진위확인에 추가 입력값이 필요한 경우 화면에서 해당 값을 별도로 받아 검증한다.
- API 키가 없는 개발환경은 mock adapter를 사용하되 실제 조회처럼 오인되지 않도록 `테스트 데이터`로 표시한다.
- API 응답 원문 전체를 불필요하게 저장하지 않는다.
- 사업자번호 입력만으로 기업 계정이나 기존 기업 프로필을 찾거나 노출하지 않는다.

## 3. 기업 프로필 필드(모두 선택 입력)
- 사업자등록번호(상태조회용)
- 기업명
- 대표자명
- 소재지(시/도, 시/군/구)
- 업종/산업분류
- 설립일
- 매출 규모 구간
- 종업원 수 구간
- 기업부설연구소/전담부서 여부
- 벤처기업 여부
- 수출 여부
- 기술 분야/보유 기술
- 기타 선택 항목은 필요성이 검증된 경우에만 추가

## 4. 자격 평가 모델
각 조건은 다음 상태 중 하나:
- `MET`: 입력된 정보로 충족 확인
- `NOT_MET`: 입력된 정보로 미충족 확인
- `UNKNOWN`: 정보 미입력, 원문 모호, 자동 판정 불가

전체 결과:
- 미충족 조건이 하나라도 명확하면 `미충족 가능성 높음` 또는 명시적 미충족
- 미충족이 없고 확인 필요가 있으면 `확인 필요`
- 모든 필수 조건이 충족으로 확인되면 `충족 가능성 높음`
단, 공고 원문 근거와 판정 사유를 함께 표시한다.

## 5. 점수화
초기에는 단순하고 설명 가능한 규칙을 사용한다. 점수는 참고용이며 법적 자격판정처럼 표현하지 않는다. 미입력 항목 때문에 점수를 과도하게 낮추지 않는다.

## 6. 기업정보 입력 UX
사업자번호 입력 → 상태조회 → 조회 결과 표시 → 추가 정보 선택 입력 → 추천 실행. 입력 생략 가능. 저장 여부와 목적을 분명히 안내한다.
