# 테스트 계획 및 완료 기준

## 1. 단위 테스트
- 공고 정규화
- 중복 판정
- 접수 상태 계산
- 분야/지역 필터
- 자격 조건 평가(MET/NOT_MET/UNKNOWN)
- 파일 내보내기 데이터 변환

## 2. 통합 테스트
- 원천 어댑터 → DB 저장
- 검색 API → 필터·정렬·페이지네이션
- 사업자 상태조회 adapter(mock 포함)
- 회원가입·로그인·세션
- 기업 프로필 저장·수정·삭제
- 추천 결과 및 근거 표시
- XLSX/CSV/PDF 생성

## 3. 권한/보안 테스트(필수)
1. 비회원은 기업별 이력·프로필에 접근할 수 없다.
2. 인증 미완료 회원은 기업별 데이터에 접근할 수 없다.
3. 기업 A 사용자는 기업 B 데이터에 접근할 수 없다.
4. 요청의 company_id를 바꾸어도 권한 우회가 불가능하다.
5. 사업자번호만으로 기존 기업 데이터가 조회되지 않는다.
6. 계정 존재 여부를 응답 차이로 쉽게 추측할 수 없다.
7. 비밀번호·사업자번호·토큰이 로그에 노출되지 않는다.
8. 관리자 API를 일반 회원이 호출할 수 없다.

## 4. 사용자 시나리오 테스트
- 비회원이 전국 R&D 공고를 검색하고 원문을 연다.
- 경기도/시흥시 지역 공고를 필터링한다.
- 사업자번호 상태조회를 수행한다.
- 선택 기업정보만 입력하고 추천을 받는다.
- 미입력 항목이 `확인 필요`로 나타난다.
- 회원이 관심 공고를 저장하고 재로그인 후 확인한다.
- 현재 검색 조건으로 XLSX/CSV/PDF를 내려받는다.

## 5. 완료 기준
- 핵심 사용자 흐름이 정상 동작
- 필수 테스트 통과
- 심각/높음 수준의 보안 결함 미해결 상태가 아님
- 데이터 출처·최종 확인 시각 표시
- API 키 없이도 mock으로 개발·테스트 가능
- 실제 API 연계가 미완료인 경우 미완료 상태와 설정 방법을 명확히 표시
- README의 설치·실행·테스트 절차 검증
