# 공고 데이터 수집 명세

## 1. 목표
전국 중앙부처·공공기관·지자체·지역 유관기관의 기업지원사업을 단계적으로 통합한다. 초기에는 주요 원천부터 안정적으로 운영하고, 이후 지역기관을 확장한다.

## 2. 초기 우선순위(조사 대상)
1. 기업마당
2. 중소벤처기업부 및 중소벤처기업 관련 공식 공고/API
3. K-Startup
4. 과학기술정보통신부 공고
5. IRIS 국가연구개발사업 관련 공고
6. 중소벤처24
7. 판판대로
8. 경기도 및 경기테크노파크 등 지역기관
9. 시흥시 및 시흥산업진흥원 등 지역기관
10. 기타 지자체·지역 테크노파크·산업진흥기관

위 목록은 조사·개발 우선순위이며, 모든 기관의 API 제공이나 자동수집 허용을 보장하지 않는다.

## 3. 수집 방식 우선순위
1. 공식 Open API
2. 공식 RSS/공개 데이터
3. 이용약관과 robots 정책을 준수하는 공개 웹페이지
4. 공식 제휴·데이터 제공
5. 관리자 수동 등록 및 사용자 제보

로그인·접근제한·CAPTCHA 우회, 비공개 데이터 수집, 과도한 요청은 금지한다.

## 4. 원천별 어댑터
각 원천을 독립 어댑터로 구현한다.
- `fetch()`: 원천에서 목록/상세 데이터 취득
- `normalize()`: 공통 공고 스키마로 변환
- `validate()`: 필수 필드·URL·날짜 검증
- `deduplicate()`: 중복 판정
- `upsert()`: 신규/변경 저장
- `report()`: 실행 결과 기록

한 원천의 장애가 다른 원천 수집을 중단시키지 않도록 한다.

## 5. 표준화 필드
사업명, 지원기관, 분야, 지역, 대상, 지원내용, 지원금액, 접수 시작·마감일, 신청방법, 제출서류, 문의처, 원문 URL, 첨부파일, 공고번호, 최초 수집일, 최종 확인일.

모르는 값은 추정하지 말고 NULL/확인 필요로 둔다.

## 6. 중복 제거
우선순위:
1. source_id + source_notice_id
2. canonical_url
3. 기관 + 공고번호
4. 정규화 사업명 + 기관 + 접수기간 + 내용 해시
중복 병합 시 원천 출처와 원본 링크를 잃지 않는다.

## 7. 갱신 정책
- 원천별 허용 쿼터와 갱신 주기를 설정한다.
- 마감 전 공고와 최근 공고를 우선 확인할 수 있다.
- 접수 상태는 서버가 날짜만으로 추정할 때 `추정`임을 표시한다. 원문에서 확인한 상태와 구분한다.
- 원문 변경 감지 시 `last_checked_at` 및 변경 이력을 갱신한다.
- 실패 시 지수형 재시도와 오류 로그를 적용한다.

## 8. 운영 화면
원천별 활성화 여부, 마지막 성공, 마지막 오류, 수집 건수, 다음 실행 예정, 쿼터/제한 메모를 표시한다.

## 9. 준수사항
API 키 발급·이용약관·재배포 가능 범위·출처 표시 요건을 실제 연동 전에 확인하고 기록한다. 수집 데이터는 원문 출처와 함께 제공한다.
