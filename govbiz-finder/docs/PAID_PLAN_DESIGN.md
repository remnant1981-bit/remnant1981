# 유료화 설계안 (v0.1, 2026-11-12) — 승인 전 구현하지 않음
가격·전환율은 모두 **검증 전 가설**. DB·인증·결제 변경이 포함되므로 단계별로 승인 후 진행한다.

## 1. 추천 방향: 무료 핵심 + 유료 '업무 도구'
| 원칙 | 내용 |
|---|---|
| 무료 유지 | 검색, 공고 상세, 맞춤 추천(우선 추천 포함), 게스트 모드, 관심 공고 저장 |
| 유료 대상 | 공고 **데이터가 아니라 업무 기능**(진행 관리·팀 협업·알림·리포트)에 과금 |
| 이유 | ① 인계 원칙(기본 검색·추천 무료) 유지 ② 정부도 무료 AI 추천을 추진 중이라 '정보 열람' 과금은 경쟁력 없음 ③ 공공 데이터 재판매 논란 회피 |

## 3. 결제 방식 — 2단계
| 단계 | 방식 | 이유 |
|---|---|---|
| 1단계(출시) | **계좌이체 + 세금계산서, 관리자가 수동 활성화** | B2B는 세금계산서 수요가 큼. PG 심사·연동 없이 바로 시작. 초기 고객 수십 곳까지 충분 |
| 2단계(유료 20곳 이상) | PG 정기결제(토스페이먼츠 또는 포트원) | 카드 자동 갱신. 통신판매업 신고·PG 심사 필요 |

## 4. 필요한 변경(승인 대상)
### DB (마이그레이션 0010~, 기존 테이블 변경 없음·추가만)
| 테이블 | 용도 |
|---|---|
| `plans_subscriptions` | 기업별 요금제, 시작·만료일, 상태(trial/active/expired), 결제 메모 |
| `pipeline_items` | 기업×공고 진행 단계, 담당자, 목표일, 결과 |
| `pipeline_notes` | 진행 건별 메모(작성자·시각) |
| `consents` | 약관·마케팅 수신 동의 기록(버전·시각) |
### 인증·권한
- 기능 권한 검사 함수 1곳(`canUse(company, feature)`)으로 통일. 만료 시 **데이터는 유지, 유료 기능만 읽기 전용**.
- Team: 기업 구성원 초대(기존 `company_members` 활용, 역할 owner/member 추가).
- 비밀번호 재설정(이메일) — 유료 출시 필수.
### 외부 서비스
- 이메일 발송(예: 네이버웍스 SMTP 또는 발송 API) — 개인정보 처리위탁 고지 필요.

## 5. 단계별 계획
| 단계 | 내용 | 승인 필요 |
|---|---|---|
| A | 진행 관리(파이프라인) + 메모 — 에스엠지 사내에서 먼저 사용 | DB 추가 — **구현 완료(2026-11-13)** |
| B | 요금제·권한 검사, 관리자 수동 활성화, 체험 기간 | DB 추가 |
| C | 이메일(비밀번호 재설정·알림) | 외부 서비스 |
| D | 약관·환불 규정·개인정보처리방침 확정, 요금 안내 페이지 | 문구 확정 — 초안 작성(`TERMS_DRAFT.md`, `REFUND_POLICY_DRAFT.md`), `[확정 필요]` 항목·전문가 검토 대기 |
| E | 운영 서버 배포, 백업 복구 연습 | 배포 |
| F | PG 정기결제(고객 수 확보 후) | 결제·사업자 신고 |
권장 순서: A → E → B·C·D → F. A는 사내 버전 요청과도 겹쳐 가장 먼저 가치가 생김.
