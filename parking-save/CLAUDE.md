# CLAUDE.md — ParkingSave

## 프로젝트 목표
전국 공영주차장 정보를 통합하고, 목적지 또는 현재 위치와 주차 예정 시간에 따라 무료·저렴한 주차장을 비교 추천하는 모바일 우선 서비스다.

## 반드시 지킬 제품 결정
1. 초기 데이터 범위: 공영주차장만. 민영주차장 제외.
2. 시설 유형: 노상·노외 모두 포함. 무료 개방 시설 포함.
3. 검색 기준: 현재 위치 또는 목적지 검색을 모두 지원.
4. 시간 입력: 주차 시작 일시와 종료 일시를 입력. 빠른 선택(예: 1시간/2시간/3시간)과 직접 입력을 제공.
5. 요금: 평일·주말·공휴일·시간대별 운영 및 요금 규칙을 반영. 확인되지 않은 규칙은 추정 금지.
6. 결과: 예상 요금, 거리, 주차면수, 운영시간, 데이터 출처·기준일을 표시.
7. 실시간 잔여면수: 제공 시설만 수치 표시. 미제공 시설은 `실시간 확인 불가`.
8. 혼잡도: 실시간 잔여면수와 총 주차면수가 모두 유효할 때만 비율 기반으로 표시. 데이터가 없으면 표시하지 않거나 확인 불가로 표시.
9. 지도: 초기에는 네이버 지도 앱 호출/딥링크를 우선 검토. 자체 내비게이션을 만들지 않는다.
10. 데이터 파이프라인: 서버 수집 → 원천 보존 → 정규화 → 중복/품질 검사 → DB 저장 → 서비스 API.

## 개발 지침
- 구현 전 관련 문서를 읽고, 문서 간 충돌이 있으면 `OPEN_ISSUES.md`에 기록한다.
- 실제 API 명세, 인증, 호출 제한, 라이선스, 갱신 주기를 검증하지 않고 임의로 확정하지 않는다.
- API 키와 비밀값은 환경변수로만 관리한다. 저장소에 커밋하지 않는다.
- 모든 시간은 저장 시 명확한 타임존을 사용하고, 서비스 표시 기준은 `Asia/Seoul`로 한다.
- 요금 계산은 단위 테스트 가능한 순수 도메인 로직으로 분리한다.
- 원천 데이터의 값과 정규화된 값을 구분해 보관한다.
- 데이터가 누락되었다고 무료 또는 이용 가능으로 간주하지 않는다.
- 오류·빈 결과·오래된 데이터 상태를 UI에 명시한다.
- 접근성, 모바일 화면, 로딩/오류/빈 상태를 함께 구현한다.

## 권장 기술 구조
기술 스택은 `docs/ARCHITECTURE.md`의 제안안을 출발점으로 삼되, 기존 저장소가 있으면 먼저 구조를 파악하고 불필요하게 재구성하지 않는다. MVP에서는 단순하고 유지보수 가능한 구성을 우선한다.
