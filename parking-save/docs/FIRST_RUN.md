# 첫 실호출 검증 런북 (API 키 발급 후)

현재 코드는 **합성/샘플 데이터로만 검증**되어 있다. 아래 순서로 실제 원천을 처음 호출하고, 결과를 `docs/OPEN_ISSUES.md` 결정 기록에 남긴 뒤 `docs/RELEASE_STATUS.md`를 갱신한다. 한 단계라도 기대와 다르면 **다음 단계로 넘어가지 말고** 원인을 기록한다.

## 0. 키 발급과 설정
| 키 | 발급처 | 용도 |
|---|---|---|
| `DATA_GO_KR_SERVICE_KEY` | 공공데이터포털 활용신청: 전국주차장정보표준데이터(15012896), 한국천문연구원 특일 정보(15012690). 둘 다 자동승인, 개발계정 일 10,000건 | 표준데이터·공휴일 |
| `SEOUL_OPENAPI_KEY` | 서울 열린데이터광장 인증키 신청 | 서울 시영주차장 실시간(OA-21709) |
| (선택) 한국교통안전공단 주차정보 제공 API(15099883) | 공공데이터포털 활용신청 | 서울 외 실시간 후보 — 기술문서 확인 후 어댑터 별도 구현 |

- `.env.local`에만 기록(커밋 금지). 서비스키는 포털의 **Decoding/Encoding 키 중 어느 쪽이 맞는지**가 원천마다 다를 수 있다 — 인증 오류(코드 30·20)가 나면 반대쪽 키로 한 번 시도.
- `ADMIN_API_TOKEN`: `openssl rand -base64 32`로 생성(32자 이상). `SITE_URL`: 운영 도메인.
- 키가 채팅·로그·커밋에 노출되면 즉시 폐기 후 재발급.

## 1. 공휴일 (`npm run sync:holidays`)
기대: `status: SUCCESS`, 두 해 모두 `complete: true`, `coverage`가 당해 1/1 ~ 내년 12/31.
- `years[].reason`이 `CANARY_MISSING`이면 그 해가 아직 미공표 — 정상일 수 있으나 **내년 데이터가 언제 채워지는지** 기록.
- 응답 형태가 다르면(`BAD_RESPONSE`) 실제 응답을 확인해 `parseHolidayResponse`를 수정(JSON/XML 모두 시도됨).
- 명칭·건수를 「관공서의 공휴일에 관한 규정」 제2·3조(대체공휴일, 선거일)와 대조. **임시공휴일이 반영되는지**(최근 지정 사례), **일요일이 목록에 없는 것이 정상인지** 기록.
- 기록: OPEN_ISSUES #4 (오퍼레이션명 `getRestDeInfo` 확정 여부, 반영 속도, 지방공휴일 제외).

## 2. 표준데이터 (`npm run sync:standard`)
기대: 전국 수천~수만 행. 소요 시간·호출 수(= 총건수 / 페이지 크기)를 기록. 일 10,000건 한도 주의.
- 실패 `API_22`(일 한도)·`API_23`(초당 한도) → 페이지 크기를 키우거나(`STANDARD_PAGE_SIZE`) 재시도 간격 조정.
- `npm run profile`로 **값 분포 확인**(핵심 점검 항목):
  - `주차장구분` 값 집합(`공영`/`민영` 외 값은? 미기재 비율) — 정규화기는 `공영`만 PUBLIC으로 인정.
  - `주차장유형` 값 집합(`노상`/`노외`/`부설` 외 값은 현재 **범위 제외**로 분류됨 → 누락 시설이 없는지 확인).
  - `요금정보` 값 집합(`무료`/`유료` 외 `혼합` 등), 기본시간·요금·추가단위 결측률, 1일권·정기권 비율.
  - 운영시각 표기 형식(`HH:MM`만 지원; `HHMM` 등이 많으면 정규화기 수정 필요), `운영요일` 표기 변형.
  - 좌표 결측·범위 밖 비율, 지번주소 결측 비율(서울 연결 후보 생성에 필요).
- `npm run quality`: 알림(좌표 불량률, 요금 계산 불가 비율, 중복 후보 등) 검토 → 임계값이 현실에 맞는지 조정하고 기록.
- 기록: OPEN_ISSUES #1 (봉투 형태, 페이지 상한, 값 분포, 행 수, 갱신 주기 — 파일별로 다르므로 `referenceDate` 분포).

## 3. 서울 실시간 (`npm run sync:seoul`)
기대: `lots: 122`, `snapshots` ≈ 122(제공처 상태 코드가 "1"이 아닌 시설은 `unavailable`로 집계).
- **https 지원 여부 확인**: `SEOUL_OPENAPI_BASE=https://openapi.seoul.go.kr:8088` 시도. 안 되면 http 사용 사실과 키 노출 위험(평문 전송·URL 경로)을 기록하고 운영 판단.
- `npm run duplicates`로 후보 목록 검토. 승인 기준: **지번 주소 일치 + (시설명 또는 주차면수 일치)**. 이름·면수가 모두 다르면 보류/거절. 같은 지번에 후보가 여럿이면 하나만 승인. `approve <id> --by 이름`.
- 매칭률(122곳 중 후보가 생긴 비율)과 거절 사유를 기록. 낮으면 주소 정규화 규칙 보완(`seoulAddressKey`).
- 5분 간격 실행 시 갱신시각(`NOW_PRK_VHCL_UPDT_TM`)이 실제로 움직이는지, 시간대가 KST인지(현재 시각과 비교) 확인.
- 기록: OPEN_ISSUES #3.

## 4. 화면 확인
`npm run dev` → 서울 시청 부근 검색: 요금·운영 상태·실시간(관측시각)·"추정" 표시·출처/기준일. `PARKING_MOCK_DATA=false`로 목업을 끄고 확인. `npm run a11y` 재실행.

## 5. 실기기 — 네이버 지도 앱 호출 (Android·iOS 각각)
| 시나리오 | 기대 |
|---|---|
| 앱 설치됨: 자동차 길찾기 | 앱이 열리고 목적지가 주차장 좌표·이름 |
| 앱 설치됨: 도보 길찾기(목적지 검색) | 출발 = 주차장, 도착 = 검색한 목적지 |
| 앱 미설치 | Android: Play 스토어로 이동 / iOS: 안내 문구 + 앱스토어 링크 |
| 좌표·주소 복사 | 클립보드에 복사, 실패 시 안내 |
- 기록: OPEN_ISSUES #9, 이용 약관·브랜드 표기 정책 확인 결과.
