## 3. 배포

### 3.1 배포 구조
| 항목 | 내용 |
|---|---|
| 저장소 | `remnant1981-bit/remnant1981` (공개) |
| 폴더 | `rnd-budget/` → 사이트의 `/rnd-budget/` |
| 배포 | `main` 병합 시 GitHub Actions(`pages.yml`)가 자동 배포, 1~2분 |
| 검증 | 병합 전 자동 테스트(단위 44건, E2E 186건) 통과 필수 |
| 설정 | `rnd-budget/config.js` — 기능 스위치, 통계·광고 ID, 문의처, 관리자 암호화 값 |

### 3.2 배포 절차(매번 동일)
1. 브랜치에서 수정 → PR 생성 → 자동 테스트 통과 확인
2. 운영자 "승인" → 병합
3. 1~2분 뒤 실사이트에서 핵심 동작 확인(정부출연금 입력 → 점검 → 엑셀 다운로드)
4. 배포가 실패하면 같은 실행을 다시 돌리지 말고 **새 실행**으로 배포(같은 실행을 재실행하면 배포 파일이 중복돼 다시 실패함 — 2026-11-17 발생)

### 3.3 단계적 공개
새 기능은 스위치를 꺼 둔 채 배포하고, 관리자 화면의 미리보기로 확인한 뒤 켠다.

| 순서 | 공개 대상 | 조건 |
|---|---|---|
| 1 | 세부 비목 | 운영자가 미리보기로 입력 흐름 확인 |
| 2 | 부처·사업 유형 선택 | 산업부 고시의 2026년 개정 여부 재확인 후 |
| 3 | 여러 안 저장 | 사용자 요청이 확인되면 |

### 3.4 전용 도메인(선택, 권장)
| 항목 | 내용 |
|---|---|
| 장점 | 애드센스 신청 가능성, 주소 신뢰도, 검색 결과에서 브랜드로 인식 |
| 단점 | 연 비용, 주소 변경에 따른 검색 재등록 |
| 시점 | **검색 등록 전에 결정**하는 것이 좋음(등록 후 바꾸면 노출이 초기화됨) |
| 주의 | 같은 저장소의 쿠폰 지갑 앱도 주소가 함께 바뀜. 분리하려면 이 도구만 별도 저장소로 옮기는 방법이 있음 |

## 5. 수익화

### 5.1 원칙
- 편성·점검·엑셀은 **계속 무료**. 유료화하면 틈새 도구는 방문 자체가 줄어든다.
- 광고·제휴는 **입력 흐름을 가리지 않는 위치**에만 두고 "광고/제휴"로 표시한다.
- 점검 결과는 제휴와 무관해야 한다(중립성).

### 5.2 단계별 수익원
| 단계 | 수익원 | 내용 | 선행 조건 | 판단 기준 |
|---|---|---|---|---|
| 1 | 디스플레이 광고 | 애드센스 2곳(코드 준비됨, ID만 입력) | 도메인, 개인정보 안내, 승인 | 방문이 적으면 수익도 작음 — 기대치를 낮게 |
| 2 | 직접 제휴 | 과제 컨설팅·세무회계(정산)·특허사무소·기업부설연구소 인정 대행 등 1~3곳 고정 노출 | 방문·다운로드 통계(제안서 근거) | 월 다운로드 수가 제안 가능한 수준인지 |
| 3 | 디지털 상품 | 편성·정산 체크리스트, 실무 가이드북, 고급 엑셀 양식 | 사업자등록, 통신판매업 신고 | Q&A 열람·검색어에서 수요 확인 |
| 4 | 상담 연결 | "계획서·정산 검토 받기" → 동의 후 파트너 연결 | 동의·제3자 제공 고지, 파트너 계약 | 오류가 많은 사용자 비율 |
| 5 | 기관용 버전 | 테크노파크·창업보육센터·대학 산학협력단용 전용 버전·교육 | 영업, 사례 | 기관 문의 발생 여부 |

방문 규모가 작은 전문 도구는 일반 광고보다 **2·5번이 수익의 중심**이 될 가능성이 높다. 단, 이는 가설이며 실제 방문·다운로드 수를 보고 판단한다.

### 5.3 수익화 준비 상태
| 항목 | 상태 |
|---|---|
| 광고 영역(상단·하단) | 구현됨, ID 입력 시 표시 |
| 개인정보 처리 안내 | 구현됨(통계·광고 설정에 따라 문구 자동 변경) |
| 통계(제휴 제안 근거) | 구현됨, 측정 ID 입력 필요 |
| 제휴·상품 안내 영역 | 미구현 — 2단계 진입 시 기능 스위치로 추가 |

## 6. 지표와 전략 수립

### 6.1 보는 숫자(깔때기)
```
검색 노출 → 클릭(방문) → 활성화(정부출연금 입력) → 편성 완성(오류 없음) → 엑셀 다운로드 → 재방문
```
| 단계 | 낮을 때 의심할 곳 | 대응 |
|---|---|---|
| 노출 | 검색 등록·글 부족 | 등록 확인, 글 추가 |
| 클릭률 | 제목·설명이 약함 | 문구 수정 |
| 활성화율 | 첫 화면이 어렵거나 대상이 아님 | 첫 화면 개선, 유입 검색어 확인 |
| 완성률 | 입력이 복잡하거나 오류를 못 고침 | 도우미·고치기 사용률 확인 |
| 다운로드율 | 결과물 신뢰 부족 | 엑셀 양식 개선, 의견 수집 |
| 재방문 | 한 번 쓰고 끝 | 집행 현황판·백업 안내 |

### 6.2 지표 시트
`docs/rnd-budget/KPI_TRACKER.xlsx`

| 시트 | 용도 |
|---|---|

| 월간요약 | 월별 자동 합산 |
| 채널별유입 | 방문이 어디서 왔는지 |
| 콘텐츠성과 | 글별 노출·클릭·도구 유입 |
| 검색어 | 검색어별 실적과 대응 |
| 목표가설 | 지표별 현재값·목표·근거 |
| 실행기록 | 한 일과 숫자 변화 |
| 지표정의 | 각 숫자의 뜻과 확인 위치 |

### 6.3 수집하는 것과 하지 않는 것
| 수집 | 수집하지 않음 |
|---|---|
| 방문 수, 기능 사용 횟수(엑셀 다운로드, 도우미, 공고문 가져오기 등), 기관 유형 구분 | 금액, 기관명, 과제명, 참여연구원 정보, 검색어 내용, 올린 파일 |

측정 ID를 넣기 전에는 통계 코드를 아예 불러오지 않는다.

## 7. 운영

### 7.1 정기 업무
| 주기 | 할 일 | 소요 |
|---|---|---|
| 매주(월) | 지표 시트 주간지표 입력, 실사이트 핵심 동작 확인 | 20분 |
| 매주 | 블로그 글 1편 | 1~2시간 |
| 매월 | 법령·고시 개정 확인(법령정보센터), 검색어 시트 갱신, 실행기록 점검 | 1시간 |
| 분기 | 목표가설 재검토, 수익원 단계 판단 | 1시간 |
| 수시 | 문의·오류 제보 대응 | - |

### 7.2 법령 갱신(가장 중요한 운영 업무)
이 도구의 가치는 기준의 정확성에 있다.

| 확인 대상 | 현재 기준 | 다음 확인 |
|---|---|---|
| 국가연구개발혁신법 시행령 별표 1 | 2026.3.10. 개정 | 매월 |
| 연구개발비 사용 기준(과기정통부 고시) | 제2026-38호, 2026.5.6. 시행 | **2026년 12월** — 개정안 행정예고 중(시행 예정 2027.1.1.) |
| 산업부 공통 운영요령 | 제2024-218호, 2024.12.30. | 부처 선택 공개 전 재확인 |
| 중기부 운영요령 | 제2026-6호, 2026.1.21. | 분기 |

개정 시: 원문 확인 → 기준값·조문 표기·Q&A 수정 → 기준일 갱신 → 테스트 → 배포 → 블로그 공지.

### 7.3 장애·오류 대응
| 상황 | 조치 |
|---|---|
| 사이트가 안 열림 | GitHub 상태 확인 → 최근 배포 실행 확인 → 새 실행으로 재배포 |
| 계산 오류 제보 | 재현 → 원인 수정 + 같은 경우를 테스트에 추가 → 배포 → 제보자에게 회신 |
| 잘못된 기준 발견 | 최우선 수정. 영향 범위를 Q&A 또는 화면에 공지 |
| 사용자 데이터 분실 문의 | 브라우저 저장 방식 안내, 백업·엑셀 다시 올리기 안내(운영자는 복구 불가) |

### 7.4 관리자 화면(`admin.html`)
| 기능 | 내용 |
|---|---|
| 비밀번호 | 화면에서 직접 설정. 암호화 값만 설정 파일에 들어가고 원문은 저장·전송되지 않음 |
| 기능 스위치 | 이 브라우저에서만 켜 보는 미리보기, 운영 반영용 설정 만들기 |
| 운영 설정 | 통계 ID, 광고 ID, 문의처 입력 → `config.js` 파일 생성 |
| 런칭 점검표 | 설정 누락·필수 파일·법령 기준일 경과 자동 점검 |

한계: 서버가 없어 **화면 가림 수준의 보호**다. 관리자 화면에서 다루는 값은 모두 공개 설정이므로 비밀번호·키·토큰은 절대 넣지 않는다. 설정은 파일을 배포해야 실사이트에 반영된다.
