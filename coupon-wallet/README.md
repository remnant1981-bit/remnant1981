# 쿠폰 지갑 (개인용 PWA)

쿠폰 만료 / 적립 진행(프리퀀시·별·스탬프)을 한곳에서 관리하는 개인용 앱. 빌드 도구·서버 없음 (정적 파일).

## 기능
- **쿠폰**: 브랜드·혜택·가치·만료일·번호·바코드 이미지, 검색, 상태/브랜드 필터, 사용 완료(절약 금액 기록)
  - 바코드 상세 화면은 **화면 꺼짐 방지**(결제 중 유지)
  - 삭제·사용 완료는 **실행 취소** 가능
- **적립**: 현재/목표/마감일/보상, ±1(연타 가능), **남은 기간 대비 필요 페이스**, 달성 불가 경고, 진행 중/완료·마감 지남 구분
- **홈**: 사용 가능 쿠폰 수, 이번 달 절약/놓친 금액, 누적 절약, 사용률, 7일 내 만료, 진행 중 적립
- **알림**: 앱을 열 때·앱으로 돌아올 때, 그리고 (지원 기기에서) 백그라운드 점검 시 만료 3일 이내 쿠폰·마감 7일 이내 적립을 하루 1회 알림
- **백업**: JSON 내보내기 / 불러오기(병합, 형식 검증), 마지막 백업 일자 표시
- **기프티콘 자동 인식**: 쿠폰 추가 화면의 "📷 기프티콘 사진으로 자동 입력"
  - 기기 내장 바코드 판독(지원 기기)으로 **번호**를 읽고, 설정에 등록한 본인 Anthropic API 키로 Claude가 **브랜드·상품·금액·유효기간·메모**를 추출함
  - 번호는 바코드 판독값을 우선(숫자 오독 방지)하고, AI가 읽은 번호와 다르면 경고함. 결과는 폼에만 채우며 **확인 후 저장**
  - 키가 없어도 바코드 번호와 사진 첨부는 동작함. 모델은 설정에서 선택(기본 Opus 5.5, Sonnet 5.5·Haiku 5.5 가능)
- **공유하기로 바로 받기**: 카톡 등에서 사진을 "공유" → **쿠폰지갑**을 고르면 앱이 열리면서 자동 인식까지 이어짐
  - 여러 장을 한꺼번에 공유하면 한 장씩 처리하고, 저장하면 다음 사진이 바로 열림. 앱을 닫아도 남은 사진은 유지됨
  - 글만 공유되면 메모에 넣어 줌
- **편의**: 폰 뒤로가기로 팝업 닫기, 아이콘 길게 누르기 바로가기(쿠폰 추가·적립), 오프라인 동작, 다크 모드

## 데이터 저장
- 브라우저 **IndexedDB**(이 기기 전용, 앱 서버 없음. 기프티콘 자동 인식을 쓸 때만 해당 사진이 Anthropic API로 전송됨). v1.0의 localStorage 데이터는 첫 실행 때 자동 이전됨
- 저장은 트랜잭션 단위(전부 성공 또는 전부 취소). 저장 실패 시 입력 내용을 유지하고 안내함
- 영구 저장(persist)을 요청해 브라우저의 임의 삭제 위험을 낮춤. 그래도 **기기 변경·브라우저 데이터 삭제 시 사라지므로 주기적 백업 필요**

## 기프티콘 자동 인식 — 개인정보·비용
- **사진이 Anthropic API로 전송됨**(바코드·쿠폰번호 포함). 공용·타인 기기에서는 키를 등록하지 말 것
- API 키는 이 기기 브라우저(IndexedDB)에만 저장되며 **백업 파일에 포함되지 않음**. 앱 서버는 없고 브라우저가 Anthropic API를 직접 호출함(공식 SDK, `dangerouslyAllowBrowser`)
- 키는 console.anthropic.com에서 발급하고 **사용 한도(spend limit)를 낮게 설정**해 두는 것을 권장. 키가 유출돼도 피해가 한도로 제한됨
- 장당 비용(추정): Opus 약 20~40원 / Sonnet 약 10~20원 / Haiku 1원 미만. 정확도가 부족하면 Opus, 비용이 중요하면 Haiku
- 바코드 판독(`BarcodeDetector`)은 Android 크롬 등 지원 기기에서만 동작함

## 실행
```bash
cd coupon-wallet
python3 -m http.server 8000   # http://localhost:8000
```

## 폰(Android)에 설치
배포 주소: https://remnant1981-bit.github.io/remnant1981/ (GitHub Pages, `main`에 `coupon-wallet/` 변경이 병합되면 자동 배포).
Android Chrome에서 위 주소 접속 → 메뉴(⋮) → "홈 화면에 추가" 또는 "앱 설치". 설치 후 앱에서 설정(⋯) → "알림 허용".
설정 화면 하단의 버전으로 업데이트 적용 여부를 확인할 수 있음.

### 공유하기로 받기 (카톡 기프티콘)
1. 카톡 채팅의 기프티콘 이미지를 길게 눌러 **공유**하거나, 갤러리·스크린샷 직후의 **공유** 버튼 사용
2. 공유 목록에서 **쿠폰지갑** 선택 → 앱이 열리고 자동 인식됨 → 내용 확인 후 저장
- **앱을 설치한 경우에만** 공유 목록에 나타남. 이미 설치해 둔 앱은 새 기능이 반영되기까지 하루 정도 걸릴 수 있으며, 바로 쓰려면 앱을 삭제하고 다시 설치함
- 카톡 선물함의 기프티콘 상세 화면에 공유 버튼이 없으면 **이미지 저장 → 갤러리에서 공유** 순서로 사용
- 자동 인식(API 키 등록)을 쓰지 않아도 공유로 사진과 바코드 번호는 받아 옴

## 구조
| 파일 | 역할 |
|---|---|
| `logic.js` | 순수 로직(날짜·상태·페이스·통계·입력 검증, 인식 스키마·프롬프트·파서·병합). 화면/서비스워커/테스트 공유 |
| `store.js` | IndexedDB 저장소 + 알림 점검(화면·서비스워커 공용) |
| `scan.js` | 기프티콘 인식(바코드 판독 + Claude 호출). 처음 쓸 때만 SDK 로드 |
| `app.js` | 화면·이벤트 |
| `vendor/` | 공식 `@anthropic-ai/sdk` 번들(Apache-2.0). 재생성: `scripts/coupon-wallet/build-vendor.sh` |
| `sw.js` | 오프라인 캐시(네트워크 우선, 3초 타임아웃), 공유 수신(Web Share Target), 백그라운드 점검(`periodicsync`), 알림 클릭. 이 앱 파일이 아닌 경로(같은 사이트의 `/rnd-budget/` 등)는 처리하지 않음 |

## 한계
- 브랜드 앱(스타벅스 등) 자동 연동 불가 → 수동 입력
- **백그라운드 알림은 보장되지 않음**: 크롬이 설치된 PWA의 사용 빈도에 따라 주기를 정함. 확실한 알림은 서버 푸시가 필요함
- 인식 정확도는 사진 품질에 좌우됨(번호·날짜는 저장 전에 직접 확인). 실제 API 호출 검증은 배포 후 기기에서 필요
- 공유 수신은 OS 공유 창에서만 확인할 수 있어 자동 테스트는 같은 형식의 요청을 서비스워커에 직접 보내 검증함. 실제 기기에서의 공유 목록 노출은 설치·갱신 상태에 따라 다름
- 후보: 서버 푸시 알림, 위치 기반 알림
